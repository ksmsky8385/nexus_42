# EKS 회원가입 요청 502 오류

- 발생일: 2026-11-26
- 대상: AWS EKS `default` 네임스페이스
- 작업 경로: `nexus_42/docker/ai-agent/k8s`

## 증상

`http://127.0.0.1:8080/`에서 프런트엔드는 열렸으나 회원가입 요청이 HTTP 502로 실패했다. 프런트엔드 Pod는 정상 실행 중이었지만, 요청을 전달하는 `ai-app-service:8000`의 준비된 엔드포인트는 0개였다.

## 원인과 확인 결과

1. **API Secret 누락.** API Deployment는 `envFrom.secretRef`로 `api-secret`을 참조한다. 로컬 `.env`에 값을 준비한 뒤 EKS에 Secret을 생성하는 단계가 빠져 API Pod 3개가 모두 `CreateContainerConfigError` 상태였다. Pod 오류 메시지는 `secret "api-secret" not found`였다. Kubernetes는 로컬 `.env`를 자동으로 읽지 않으므로 클러스터에 Secret이 따로 필요하다.
2. **PostgreSQL 초기화 실패.** `sql-0`은 `CrashLoopBackOff` 상태였다. PostgreSQL이 PVC 마운트 루트인 `/var/lib/postgresql/data`에서 초기화를 시도했고, 그곳에 파일시스템이 생성한 `lost+found`가 있어 `initdb`가 실패했다. 이 오류는 API Secret 누락과 별개다.

## 해결 절차

`sql/sql-statefulset.yaml`의 `sql` 컨테이너에 다음 환경 변수를 추가했다.

```yaml
env:
  - name: PGDATA
    value: /var/lib/postgresql/data/pgdata
```

대상 EKS 컨텍스트를 확인한 뒤 `k8s/`에서 실행한다. `.env`는 `.env.example`을 기준으로 준비하고, `POSTGRES_PASSWORD`는 클러스터의 `sql-secret`에 설정된 비밀번호와 일치시킨다.

```bash
kubectl config current-context
kubectl -n default apply -f sql/sql-statefulset.yaml
kubectl -n default create secret generic api-secret --from-env-file=.env
```

이번 복구에서는 실패 중이던 기존 `sql-0`이 새 설정으로 교체되지 않아 `kubectl -n default delete pod sql-0 --wait=false`로 재생성했다. 새 Pod는 기존 PVC를 사용했다.

```bash
kubectl -n default rollout status statefulset/sql --timeout=180s
kubectl -n default wait --for=condition=Ready pod -l app=api --timeout=180s
```

## 검증 결과

- PostgreSQL StatefulSet 롤아웃이 완료됐고 API Pod 3개 모두 `Ready` 상태가 됐다.
- API 로그에서 `POST /auth/register`가 `201 Created`를 반환한 것을 확인했다.
